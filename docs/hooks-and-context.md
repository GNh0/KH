# Hooks and context retention

KH bundles a shared Python 3.11+ core with separate Codex and Claude hook adapters. Hooks are short-lived commands: no background observer, extra LLM call, automatic formatter, build, database execution or MCP startup. Existing project coding-style and source-necessity audits remain the main agent's responsibility.

## Host registration and trust

Codex explicitly loads `hooks/codex-hooks.json` through `.codex-plugin/plugin.json`. Claude uses the default `hooks/hooks.json`. Codex runs command hooks through the configured shell, with a Windows command override; Claude uses the documented direct executable/args form. Both need Python available (`python` on Windows/Claude, `python3` on Unix Codex).

Review bundled hooks in the host before use. Codex requires trust for each hook/script hash; an upgrade does not silently grant it. Use `/hooks` or the desktop's Review hooks / Settings > Hooks. No cache, trust database or global configuration is edited by KH. See [Codex hooks](https://learn.chatgpt.com/docs/hooks) and [Claude hooks](https://code.claude.com/docs/en/hooks). Standalone copied skills do not install these lifecycle hooks.

`KH_HOOKS_MODE=advisory` keeps feedback without edit/Stop denial; `off` disables the core. Code checks apply only to explicit file responsibilities registered by the agent through [scoped application](../skills/work-execution/references/application.md). Skill reading and selection are availability/intent observations, not application. Automatic discovery stays enabled; the user need not name a skill or approve another setup step. A skill token, native invocation or document read cannot identify the actual development files. Enforce gates only the explicitly applied outputs; the agent must register its owned implementation files before writing and the main agent must check that step from the actual tool trace. An omitted apply remains unverified, not a pass. A skill-name mention, document inspection or another registered file does not extend ownership to excluded work. Unregistered files receive no KH source-write checks. After a matching entrypoint was available, their first otherwise unhandled write can receive a conditional outside-coverage notice; no body inspection, snapshots, activation or Stop gate follows from that notice. Unknown/malformed input, Python absence, timeout or unsupported host paths remain unverified. These are workflow checks, not a security boundary.

Codex observes complete entrypoints and required reference sections in tool returns, including segmented reads. Fresh `UserPromptSubmit` syntax (`$sql-formatting`, `$csharp-designer-style-harness`, `$pb-to-csharp-migration-harness`, `kh-uaf:` names and exact owned links) records requested skills only. Quoted examples, inline/fenced code, block quotations, host-only envelopes and foreign/unresolved linked selections are excluded by the bounded recognizer. It does not rebuild the global host catalog; use a qualified name or owned path when ambiguous.

For actual development, the agent uses `kh_context.py apply` with the current hook-supplied project/chat/agent/data-root/epoch and named files/work responsibilities. The helper writes the exact scoped intent directly; printed markers or skill-document inspection cannot register application. It returns missing current guidance sections and absolute file/line ranges, and captures immutable originals without marking documents read or an audit complete. C# code/control/Designer/grid/data/report responsibilities, SQL format/SELECT/SAVE and PB native/migration outputs have separate routes. .Designer.cs enforces its minimum Designer/control references. PB analysis/extraction does not activate C#/SQL writes. Registered C# changes additionally expand supported control/grid/report responsibilities from actual changed framework construction/receiver assignments. Ordinary methods, DTO properties and literals do not become UI work merely from property names; unresolved types/business roles remain unverified. Declared and inferred responsibilities remain separate: current saved/proposed changes determine inferred scope, so a denied proposal withdrawn before saving cannot permanently expand it. Explicit selections and still-persisted changes retain their needed scope.

Claude additionally observes owned successful namespaced `Skill` delivery and plugin `UserPromptExpansion`. Pending expansion correlation is checked on every real submission, including the cold first turn: matching IDs or an exact no-ID prompt hash bind once. Different/partially missing IDs do not fall back to text guessing. Native delivery is availability only; it does not apply development scope. Existing independently delivered evidence is preserved, and applied source intent is independent of pending selection.

After Stop/SessionEnd, the next distinct real user turn clears application, selection and prerequisite coverage. Same-task steering/compaction preserves needed application and originals; each new real turn refreshes the apply epoch so a late old helper cannot register new intent. Apply cannot resume a paused task. An upgrade removes legacy read-only activation while preserving known pending source files/originals for explicit responsibility classification; it does not apply old skill names to unrelated files.

Selected comparison sources are supplied through scoped `apply --reference <source[#Lstart-Lend]>`. A supported Read/read_file or explicit Get-Content/cat read must identify the selected source path and return its current body after selection for the registered responsibilities; registration alone is not a read. Units can be read in ranges, source changes invalidate their evidence, and owned outputs cannot certify themselves. Unknown/dynamic read commands remain unverified rather than borrowing another file's identical output. This observes current source availability only: approval, same-responsibility selection, full caller coverage and semantic comparison remain the agent's responsibility. Ordinary formatting-only SQL retains its preservation guard without adding a comparison program.

The same successful-read provenance is required for saved-file readback: a Write response, another file's identical body or a failed read cannot certify it. Responsibility-specific C# references are kept separately, and a PB original is distinct from output-language style. For actual specialist assignments, use the shared [assignment/result contract](../skills/work-execution/references/agent-contract.md).

`SubagentStop` finalizes only an observed applied child's scope. A host/session/child-id locator retains its exact tool/apply key when the end event carries the parent's transcript path; unrelated or unobserved children remain untouched. Native Codex child transcript metadata must match the child id and its parent-session relationship. The main agent still collects the actual report and performs combined regression checks. Registration and replay do not prove native host firing; installed hooks must be checked separately after an upgrade.

## What is actually checked

- Before recognized writes to applied files: current entrypoint, the single shared source-style cycle and the actual responsibility-specific reference sections must be available. Missing sections deny the edit with exact file/line locations. Whole-file reads cover their sections; unrelated sections are not required. Registration/delivery/read records establish availability and intent, not understanding or a reference-program/semantic audit.
- After writes: domain checks on actual saved files, bounded to 32 files of 1 MiB each. For observed writes, the first pre-edit source remains the comparison baseline across further edits. C# checks receive the conventional code/Designer companion and its captured original. Before/after line hashes separately identify changed text plus adjacent context; returned text can be read in numbered or split ranges. Later edits invalidate affected read evidence. Missing originals remain unverified; the current candidate is never adopted as its own original. No automatic source rewrite occurs.
- Automatic C# context: verified selected C#/Designer comparison units are passed to the actual checkers, with source/range/hash dependencies. Unread, changed or owned outputs cannot supply that comparison; multiple different programs for one comparison role remain ambiguous. A bounded scan of explicit unconditional local `Compile`/`ProjectReference` items supplies uniquely resolved, filename-matching control definitions used by the pair. Companion lookup preserves actual filename case and original identities recognize existing Windows aliases. Source/project paths and hashes are recorded; changes to the companion or those dependencies invalidate cached checks. Conditional/dynamic/imported/SDK membership, ambiguous types/projects, runtime initialization and unmatched definitions remain unverified. This is source evidence, not MSBuild evaluation, a complete control catalog or a substitute for reading the actual initialization flow.
- Screen presentation: without an explicit comparison Designer, recorded unchanged visible controls from the original screen can supply same-parent/row or same-type height evidence. The edited control and changed/new peers cannot certify themselves; conflicting or unavailable evidence remains unverified. `same_screen_members` records the selected peers. A selected role comparison or recorded unchanged same-type peer can also establish a font; changing every label together does not certify that change. Control alignment still follows the actual supplied initialization. Explicitly hidden controls/ancestors are excluded from visual size/font checks; negative coordinates alone do not prove hiding, and binding/behavior checks remain active. Compatible height constraints need not copy an unrelated control type's minimum/maximum bounds. Supported Font literals are compared by value, while screen data `EditValue` assignments remain a behavior-audit responsibility. A retained narrower control is not forced wider by an unrelated height edit; new or further width shrink still undergoes the existing rule.
- Review output: errors, counted warning codes, selected findings and `not_checked` remain separate. New warnings produce `status=review_required`, even when the underlying standalone checker has no errors. Unchanged differential findings are suppressed; that does not establish whole-file style compliance. Whole-file imports/style corrections still need standalone checks and actual reference-program comparison. Automatic SQL edits use originals to review new findings; standalone formatting comparisons retain their semantic-preservation checks and do not prohibit authorized logic edits in the hook.
- SP authorship: actual sql-select/sql-save work requires user-selected author/reference-author metadata and a current observed complete SP unit, including its actual author comment and full batch. Selection is scoped by project/chat/agent and recorded per owned file; another file's new author does not reassign prior files. New worked-on SP artifacts require the framed AUTHOR / CREATE DATE / DESCRIPTION header. Bare queries, formatting-only preservation and other domains keep their existing routes. Existing ALTER/export attribution and unsupported date/schema evidence stay reviewable rather than being replaced with the current worker. No metadata entry certifies the actual user question, first-date truth, complete SQL grammar or style compliance.
- SQL value sources: added/changed value-producing `ISNULL`/`COALESCE` and supported NULL/blank-guard `CASE`/`IIF` expressions whose normal branch returns the guarded value receive `value_fallback_review`. The agent must find the user's explicit request for that substitution in the owning operation or remove the unauthorized change. Initial editor defaults do not authorize SAVE/SELECT substitutions. Unchanged expressions, recognized formatting/alias-only changes and predicate-only NULL handling and status/aggregate classification without a preserved-value branch are separate. This bounded recognizer neither determines user authorization nor covers every equivalent SQL form; full source/requirement audit remains required.
- Cache generation: persisted checks carry package/cache generation plus applied responsibilities and required-section hashes. Artifact, peer, dependency, operation or applicable guidance changes reopen the affected check; unchanged guidance/operations and reads are reused. An upgrade or legacy result without generation forces fresh checks. Readback evidence is preserved and remaining warnings/unsupported scope are never converted into a pass.
- Before completion: missing readback, static errors, warnings or incomplete checks trigger a bounded continuation request. Readback alone does not resolve a warning. Normal repeated Stop attempts remain blocked for actual errors, unread saved changes, missing prerequisites or missing comparison evidence. Warning-only findings keep bounded repetition; native `stop_hook_active` feedback remains bounded even for unresolved errors. In each unresolved case, completion_status remains requires_repair_or_evidence and originals/results remain unresolved. This suppresses repeated transport blocking, never clears a finding or records an audit pass; a repeated unresolved result remains explicitly unverified. The agent must decide findings against actual requirements/source evidence, repair confirmed violations, re-audit and check regressions. No hook certifies semantic compliance or automatically treats a legitimate warning as a defect.

Claude's `PostToolUseFailure` rechecks supported saved destinations that actually changed before failure. An unchanged failed write creates no new saved-file audit; an interrupted failure preserves originals and pauses without starting another inspection. While paused, later tool results/Stop do not inspect source. After explicit `kh_context resume`, Stop reconciles observed write intents against the actual files, including when the completion event never arrived. Each observed file keeps its intent through the edit epoch until Stop; an individual completion cannot consume a later write to that same file. Changed files retain their first immutable original for checking and repair; unchanged intents create no new saved-file audit. Readback ranges use the most recently inspected body so retaining the original intent does not reopen already-read unaffected changes. Codex reports nonzero shell exits through `PostToolUse`, so its adapter keeps that documented event instead of registering Claude-only failure events. Claude's native `PowerShell` tool uses the same bounded destination resolver as supported shell calls. A failure after a partial write is not completion.

Comparison-source reads accept explicit PowerShell Get-Content paths with bounded -Encoding/-Raw/-TotalCount/-Tail ordering and numeric array slices. Blank lines do not count as source-observation evidence; all nonblank lines of the selected unit are still required, including across segmented returns. Unknown/dynamic commands, wrong paths and failed reads remain unverified.

Typed Edit/Write/apply_patch and bounded shell-write destinations are recognized. The shell adapter resolves common straight-line Python `Path`/string assignments and writable `open`, and simple PowerShell assignments, `Join-Path`, interpolation, content commands and `IO.File` writes. Python is recognized in invoked PowerShell here-strings, simple `python -c` and heredoc forms. Resolution uses the command's actual workdir and never executes the program to discover paths. A recognized unresolved source-shaped destination tied to an applied path in the same call is denied in enforce mode; a wholly dynamic destination cannot be assigned ownership in advance. Registered files still reconcile their actual original/candidate difference at Stop. An unresolved destination is not treated as a successful check. Quoted examples, comments, read-only operations and non-domain output files do not become domain edits.

This is a bounded syntax adapter, not a filesystem sandbox: functions, arbitrary control flow, external scripts/inputs, unsupported invocation forms, hosted tools and specialized host operations can still escape observation. It does not promise to detect every dynamic write. Source bodies returned with line-number decorations, truncation or encoding differences may need a direct complete UTF-8 read. Supported known-control indexer assignments and mutating UI receiver calls also trigger responsibility review; untyped or arbitrary helper semantics are not inferred from a method name alone. During an active edit, known files are rechecked on later events. A clean observable Stop retires that edit set as `checks_complete`, with `semantic_audit_verified=false` and `completion_status=checks_complete_audit_unverified`; this is not full audit completion. It keeps compact results for scoped recall; later read-only work does not keep reviewing completed files or other chats' subsequent changes. A new observed edit starts a new comparison epoch. Existing limits on builds/DB/other external actions still apply.

Pre-edit source bodies are content-hashed files under the existing external context store's `checks/<session-key>` directory, never under the project or plugin cache. SQLite records identities, not those bodies. At most 64 source/companion identities of 1 MiB are captured. A clean Stop deletes unchanged task-owned snapshots after preflighting the directory; unexpected/tampered files are preserved and cleanup is reported unverified. Unfinished reviews, interruption and compaction retain needed originals. These source snapshots are ordinary local files, not a credential vault. Scoped `kh_context.py recall` exposes saved check summaries/context when the short hook message omits files; it does not print snapshot bodies.

After a prior edit reaches Stop, the next distinct real user turn retires that earlier active set. Unresolved results are archived as `previous_turn_unverified`, never relabeled as passed; recall distinguishes them from current active checks. This also handles pre-upgrade sessions that retained a `stop_notice` without an epoch marker. A new observed edit captures its current pre-edit source. Same-turn steering, native Stop continuation, compaction, interruption and an explicit stop request preserve the active repair and needed originals. Cleanup still preflights ownership; a failed cleanup preserves the records and reports the limitation. Upgrading during an active turn does not infer a new task boundary.

## Legacy Codex notification errors

`legacy_notify` is Codex's global `notify` command, separate from KH's registered lifecycle hooks. Its JSON payload travels as a command-line argument; Windows error 206 can occur before that command starts. A wrapper that receives the same oversized argument does not repair that transport. When an obsolete `codex-computer-use.exe turn-ended` notification is present, first verify the enabled installed computer-use plugins already register their native `Stop`/`Interrupt` lifecycle hooks. An explicitly authorized repair can then remove only that duplicate notification, preserving the native hooks and all other settings. Do not remove arbitrary notifications or add a second CUA owner to KH. KH does not automatically rewrite global host configuration or grant hook trust.

## Compaction and durable memory

`PreCompact` saves current-chat user evidence/source locations and existing curated checkpoint. Both Codex and Claude restore through `SessionStart(source=compact)`, with duplicate suppression. A paused task or pending source audit still receives scoped recovery guidance when no user record/checkpoint was captured; lack of archived text must not erase the pause notice. Codex delivers this context before the next model request, including an immediate continuation after automatic compaction within a turn. `PostCompact` does not support context injection and is not registered by KH. Startup/resume loads the same chat's checkpoint plus explicitly curated project memories. A new chat does not inherit another chat's task checkpoint. Interruption preserves needed continuation data and does not restart the task.

Recovery is a bounded preview with original source locations. It is not a second summary that silently replaces the originals. Latest corrections/cancellations take precedence, a checkpoint records its user-record cursor, and incomplete capture is reported. The latest observed UserPromptSubmit is preserved separately even while a large transcript has pending capture; older uncaptured details still require the original log/checkpoint. Supported Codex/Claude transcript adapters are version-sensitive because host transcript formats are not stable public APIs. Images, attachments, deleted logs and unsupported formats remain unverified.

Codex capture accepts both desktop `response_item/message/role=user` text parts and `event_msg/user_message`. Adjacent mirrored representations share one archive record with both source locations; separate repeated requests remain separate. Sequence ids remain stable archive identifiers, including after backfill. Recovery, recall and search previews order comparable records by their offsets in the same selected transcript, so later insertion of historical records cannot displace the latest source correction. The most recent unlinked prompt event is retained with explicitly unverified source order. A checkpoint's additional-record count can include historical backfill and is not a count of newer user requests; recovery shows recent evidence before a long checkpoint. No total chronology between different logs or unlinked events is inferred. Adapter upgrades rewind the selected transcript once and backfill in bounded passes, preserving existing archive identifiers, checkpoints and pause state. A fully read log with no supported user records is reported as unverified rather than successfully preserved.

Native `<hook_prompt ...>...</hook_prompt>` Stop continuations are host feedback, not user requests or new edit boundaries. Capture excludes these envelopes and removes previously misclassified archive entries without renumbering real user records or reusing ids. New checkpoint cursors use archive sequence ids, so filtered gaps do not hide later corrections. A user message that quotes an envelope and adds a request outside it remains user evidence.

Use [context handoff](../skills/context-handoff/SKILL.md) to save a critical task checkpoint or explicitly requested long-term project fact. Storage is outside project/cache trees and isolated by project/chat; no native global memory is edited. Local archival is not promotion of all historical requests into permanent user preferences.
