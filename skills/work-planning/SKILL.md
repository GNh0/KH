# Work planning

First define the completed outcome from the current request and actual inputs. Reuse existing plans and approved choices. Ask only about ambiguities that change the result, and continue investigation that does not depend on the answer.

When needed, briefly plan the current structure, change scope, dependency order, and validation. Do not define planning completion by fixed headings, scores, role diagrams, or document counts. Do not ask a user who already requested implementation to approve a plan format again.

Select only the skills needed for the task from the currently available list. Do not rerun a preflight based on harness lists in old memories or handoffs. Perform separate skill discovery or create selection tables only when a skill-configuration audit or inventory is requested.

Handle small, clear questions and local edits directly. For plans where input relationships matter, such as PB migration, use the domain skill's source-analysis guidance. Lead the final explanation with the result and evidence.
