# KH 3.0.4: SQL 괄호 정렬과 화면 수정 계약

사용자가 이미 알려 준 SQL·C# 기준을 실제 작성과 검사에서 놓친 문제를 수정했다. 사용자 설명이 부족해서 새 규칙을 만든 작업이 아니다. 과거 감사에 남아 있던 파생 JOIN 요구와 현재 스킬·검사기가 서로 어긋나 있었으며, 참조 작업에서는 3.0.3 스킬을 읽은 뒤에도 기본 속성을 다시 추가하고 검사 예외로 제외한 기록이 확인됐다.

## 감사 범위와 원인

사용자가 지정한 모니터링 작업의 원문 사용자 메시지 107개를 읽고 정정·취소·반복 요구를 대조했다. 최초 스냅샷의 완료 응답 29개와 명령 호출 383개를 인덱싱하고, 문제와 연결되는 실제 명령 출력·성공한 파일 변경 기록을 선별해 확인했다. 뒤에 이어진 사용자 메시지 4개와 최종 응답도 포함한다. 다른 업무 프로젝트나 DB를 수정하지 않았다. 원문 대화·이미지·업무 소스·실제 SQL은 공개 패키지에 포함하지 않는다.

| 관찰한 문제 | 근거와 원인 | 반영 위치 |
| --- | --- | --- |
| 파생 JOIN의 닫는 괄호·ON/AND 정렬 오류 | 과거 요청은 닫는 괄호 바로 아래 ON을 요구했다. 3.0.3 문서와 검사기는 닫는 괄호를 JOIN 시작, 내부 절을 JOIN+4, ON을 일반 JOIN의 I 위치로 정했다. 요구를 잘못 보존한 KH 결함이다. | SQL 스킬·정렬기·검사기·정답 회귀 사례 |
| 중첩 FROM/UNION의 괄호와 내부 절 불일치 | 기존 검사 루프는 첫 FROM 소스를 빠뜨렸고, 기존 정렬기는 파생 쿼리의 본문·닫는 괄호를 정리하지 않았다. | 첫 FROM부터 중첩 FROM/JOIN 블록 검사, 부모 정렬 이후 자식 정렬 |
| C# 중괄호·명명·기본 속성 반복 누락 | 이미 합의한 작성 방식이 있었고 3.0.3 스킬 및 작성 방식 참고 파일을 읽은 기록도 있다. 설치 버전만으로 반복 실패를 설명할 수 없다. | 기존 C# 작성 방식 유지, 전체 스타일 점검과 변경분 보존 비교의 역할 명시 |
| 마스크 경고를 자동 예외 처리 | 생성한 EditMask 대입을 스캔해 해당 속성을 --allow-property-change로 추가한 성공한 파일 변경이 확인됐다. 통과를 만들었지만 사용자 필요성을 입증하지 않았다. | style_exemptions 공개, not_checked에 제외 범위 기록, 자동 예외 등록을 근거로 삼지 않도록 명시 |
| 마스크 제거 후 다른 표시 속성 추가 | 실제 공유 helper의 DisplayFormat 예시를 참고한 변경도 있다. helper 이름만으로 현재 컨트롤에 적용되는 기본값이나 사용자 예외를 확정할 수 없다. | 실제 초기화·현재 요구 우선, 다른 속성으로 자동 대체하지 않도록 화면 계약 보강 |
| 숫자 편집기 반복 누락 | Repository 선언이나 포맷만 있고 실제 컬럼 연결이 없거나 이후 연결이 사라지는 경로를 구분해야 했다. | 명시한 숫자 컬럼의 실제 Spin ColumnEdit 연결 검사, C#의 명시적 덮어쓰기 검사 |

| 조회 소유권·실제 SP·대표 키 연결 누락 | 각 UserControl 조회 요구에 부모 폼의 조회·예시 분기가 섞이고, 실호출·매개변수·대표 키 상세 조회 요구가 반복됐다. | 실제 UserControl/부모 역할, SP/WORKTYPE/결과 순서, 호출부만 준비하는 범위 명시 |
| 공통 Task 관리 기능 중복 | 이미 있는 실행·취소·UI 연결 기능을 폼의 별도 반복/완료 처리로 다시 만드는 변경이 있었다. | 대상 Task 관리 API를 먼저 읽고 기능별 소유권 유지 |
| 같은 페이지의 주기 조회와 전체 대상 범위 누락 | 페이지 전환과 재조회를 같은 조건으로 처리하면 활성 화면 하나에서 갱신이 빠진다. 목록·상세의 요구 시점도 다르다. | 주기 갱신·화면 진입·선택 키·상세 페이징을 구분, 전체 요청의 실제 대상과 공통 경로 확인 |
| 합계·단위·필터·표시 위치 요구 누락 | 행 비율과 전체 비율, 분/시간, Footer와 마지막 합계 컬럼, 헤더/그리드/차트의 조건을 따로 확인해야 했다. | 합계의 분자/분모, 기간·NULL·JOIN·단위·UNION 분기 계약 대조 |
| 보조 검증 프로그램 오류 | 사용자 이미지의 오류 프로세스는 임시 검증 프로그램이었다. 이후 수정·재실행 설명이 있지만 예외 상세 원인을 독립 확인하지는 않았다. | 보조 실행 실패를 제품 결함이나 통과 증거로 바꾸지 않고 실제 예외·호출·종료 상태 구분 |

후속 요구와 취소를 과거 실패로 소급하지 않았다. 문구만 제거하라는 요청과 날짜 입력 제거는 다르며, 취소한 화면 설정 요구를 다시 복구하지 않는다. 사용자가 단위 문제를 철회한 사례는 결함으로 세지 않았다. 집계 필터 관련 질문도 질문만으로 새 DB 결함이라고 확정하지 않았다. 공통 부모 경로로 여러 화면이 갱신되는 경우에는 개별 파일 변경 유무만으로 누락을 판정하지 않는다.

## 실제 수정

### SQL

[SQL 작성 기준](../../../skills/sql-formatting/references/style.md)과 [정렬기](../../../src/sql/layout.py)를 같은 규칙으로 맞췄다.

- 일반 테이블 JOIN은 현재 FROM+8, ON과 같은 JOIN의 줄 앞 AND/OR는 JOIN의 I 열에 맞춘다.
- 파생 JOIN은 소스 여는 괄호, 닫는 괄호, ON과 같은 JOIN의 줄 앞 AND/OR를 같은 열에 맞춘다. 내부 최상위 SELECT/FROM/WHERE/GROUP/UNION 등의 절은 여는 괄호보다 한 칸 오른쪽이다.
- FROM 파생 쿼리에도 같은 괄호 기준을 적용하며, 중첩 블록은 각각 자기 여는 괄호를 기준으로 한다.
- 부모 블록을 먼저 이동하고 자식 FROM/JOIN/EXISTS가 이동된 열을 사용한다. 각 절의 연속 줄은 해당 절과 함께 이동한다.
- BETWEEN의 내부 AND, CASE·하위 쿼리에 속한 조건은 바깥 JOIN 조건으로 오인하지 않는다. 함수·APPLY의 괄호를 이전 JOIN 블록으로 잘못 적용하지 않는다.
- 별칭·토큰·한글·주석·리터럴 내용을 보존한다. 주석을 통과해야 하는 인라인 분리나 지원하지 않는 SQL 구문을 무리하게 다시 쓰지 않는다.

사용자의 마지막 중첩 정답은 재정렬 후 그대로였고, 첫 잘못된 JOIN 예시는 토큰을 보존한 채 정답 배치로 바뀌었다. 실제 업무 SQL은 로컬 검증에만 사용하고, 공개 회귀 테스트는 일반화한 입력이다.

### C#과 화면 동작

[화면 동작 계약](../../../skills/csharp-designer-style-harness/references/screen-behavior.md)을 추가하고 C# 스킬 진입점에서 연결했다. 기존 사용자 작성 방식, 컨트롤 Name, 사용자 컨트롤 우선과 초기화 속성, 셀/헤더/편집 속성 규칙은 그대로 유지한다.

C#·Designer 명령에 반복 가능한 --numeric-column COLUMN_MEMBER를 추가했다. 실제 소스로 확인한 숫자 컬럼만 지정하며 필드 이름으로 타입을 추정하지 않는다. 지정한 연결은 원본과 같아도 검사한다. 컬럼이 없거나 잘못된 멤버이면 경고하고, 실제 Spin Repository가 연결되지 않았으면 경고한다. csharp --designer 명령에서는 명시적인 code-behind 대입도 대조한다. 선언·등록 검사는 기존 검사와 함께 사용한다.

--allow-property-change의 값은 결과의 style_exemptions와 not_checked에 나타난다. 제외한 스타일 검사와 실제로 확인한 계약을 구분한다. 별도 승인서나 필수 예외 파일을 요구하는 절차를 추가하지 않았다. LINQ·중간 테이블·빌드의 비선호와 사용 필요성 기준도 변경하지 않았다.

| 확인 | 결과 |

| Python 3.12.14 도메인 회귀 검사 | 194개 통과 |

| 사용자 SQL 두 사례 | 토큰·별칭 보존, 재정렬 안정성, 정렬 검사 통과 |
| 독립 SQL 작성 평가 | 원본 두 쿼리와 스킬만 주고 정리 요청. 파생 JOIN, 중첩 FROM/UNION, 일반 JOIN 정렬 확인. 검사 issues 없음 |
| 독립 C# 작성 평가 | 원본 두 파일과 폭/숫자 편집 요구만 제공. 폭 덮어쓰기 경로 제거, Spin 선언·생성·등록·연결, 13개 보존 속성 확인. 두 검사 issues 없음, 스타일 예외 없음 |

독립 평가에는 수정 정답이나 구현 방법을 전달하지 않았다. 결과 파일을 주 작업에서 다시 읽고 변경을 확인했다. 공식 플러그인 검증·10개 스킬 검증·패키지 및 보존 검사는 함께 제공한 [기계 판독 결과](2026-09-09-derived-layout-screen-contracts.json)에 기록했다. 공식 플러그인·10개 스킬·패키지 검사는 모두 통과했고, 기존 로컬 자료 25개·마켓플레이스·두 기본 프로필의 원본도 유지됐다.

## 확인 범위

이 결과는 해당 정렬과 화면 수정 사례에서 관찰한 개선이다. 모든 에이전트가 앞으로 지시를 반드시 준수한다는 보장은 아니다. 특히 스타일 경고가 있어도 결과 status는 passed일 수 있으므로 issues와 제외·미확인 항목까지 읽어야 한다.

정적 C# 검사는 실제 DevExpress 버전, 런타임 컬럼 재생성, 사용자 컨트롤 helper의 전체 실행, Visual Studio Designer와 렌더링을 증명하지 않는다. 독립 C# 평가에는 실제 프로젝트나 컨트롤 라이브러리가 없어 그 호환성과 소수 편집 실행을 미확인으로 남겼다. SQL 토큰 보존은 DB 실행 결과·계획·성능의 증명이 아니다. 이번 KH 작업에서 ERP 빌드나 DB 실행은 하지 않았다.

원문 메시지는 모두 읽었지만, 인덱싱한 전체 도구 호출의 모든 출력과 모든 이미지를 실행 검증한 것은 아니다. 보조 검증 프로그램 오류의 상세 원인과 후속 수정의 실제 UI 효과도 재현하지 않았다. 공개 게시 상태, CI, 설치 캐시는 서로 다른 상태로 확인해야 하며 패키지 수정만으로 현재 열린 작업의 스킬이 갱신되었다고 보고하지 않는다.
