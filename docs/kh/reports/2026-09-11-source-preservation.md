# KH 3.0.7 — 원본 유지 이관과 비교 기준

3.0.6을 실제로 읽고 검사까지 실행한 이관 작업에서 스타일 문제가 재발했다. 설치 버전 미갱신으로 설명할 수 없는 사례다. 사용자 정정과 최초 작성 기록을 다시 대조해 원본 보존 범위, 상태 제어, 검사 입력을 보완했다.

## 재발 원인

- 원본 화면에서 이름과 일부 컨트롤만 바꾸는 요청을 새 Designer 작성으로 처리했다. 기존 화면 속성의 보존과 새 컨트롤의 기본값 선택이 충분히 구분되지 않았다.
- 기존 원본에도 특정 상태의 제한은 있었지만, 이를 새 bool 상태로 다시 구성하면서 첨부·버튼 등 다른 동작까지 제한했다. 변수 이름 변경과 업무 정책 확장을 구분하지 못했다.
- C#/Designer 검사는 원본을 제공하지 않았다. SQL 검사는 후보를 원본 자리에 다시 넣었다. 단일 파일의 정적 검사와 실제 변경·보존 비교가 혼동됐다.
- 3.0.6의 독립 작성 평가는 미완성 화면의 이벤트 연결을 확인했다. 원본 Designer의 속성을 그대로 유지하는 이관까지 검증한 결과는 아니었다.

## 수정

원본 보존을 명시한 현재 요청은 일반적인 새 코드·새 컨트롤의 선호보다 우선한다. 원본 C#/Designer/resx를 출발점으로 수정하고, 남기는 컨트롤의 속성 및 요청 밖 동작을 다시 설계하지 않도록 스킬을 수정했다. 전체 코드 재작성이나 새로운 제한을 스타일 정리로 취급하지 않는다.

`--preserve-existing`은 남긴 Designer의 타입과 명시적 속성 대입을 원본과 비교한다. `--member-rename old=new`로 이름 대응을 제공하며 일반 Text·BindingField 문자열은 자동 치환하지 않는다. 변경·추가·누락 속성은 컨트롤별로 보고한다. 대응되지 않은 원본 멤버와 새 멤버도 결과에 남긴다.

`ui_state_policy_review`는 bool 필드로 편집·Enabled/ReadOnly·컨트롤 보호·이벤트 실행을 제어하는 새 후보를 경고한다. 기존 필드라도 제한 적용 위치가 달라지면 검토한다. 이는 bool·삼항식·업무 검증을 금지하는 규칙이 아니다. 기존 동작 또는 명시적 요청으로 필요한 상태는 사용할 수 있다.

`comparison_baselines`는 원본 제공 여부를 결과 앞부분에 표시한다. CLI에서 원본과 후보가 동일 파일이면 입력 오류로 처리하며, 하드 링크도 구분한다. 새 SQL은 한 파일만 검사할 수 있다. 별도의 정상 사본은 내용이 같아도 비교할 수 있지만 사본의 생성 시점과 출처를 자동 보증하지는 않는다.

## 실제 실패 작성본 재검사

작성 기록에 남은 최초 C#/Designer를 복원해 같은 입력으로 비교했다. 3.0.6도 다른 항목의 경고 15개는 냈지만 상태 제어와 원본 속성 전체의 비교는 없었다. 수정본은 원본 미제공 여부를 표시하고 상태 제어 후보 2개를 추가로 알렸다. 이 중에는 재진입 제어도 있으므로 모든 경고가 곧 업무 오류인 것은 아니다.

실제 이관 원본을 제공하고 속성 보존 검사를 켰을 때 같은 이름의 37개 멤버와 폼에서 365개의 대입·타입 차이를 확인했다. 이 수치는 확정된 위반 수가 아니다. 요청된 바인딩·배치 변경도 포함되며, 이름이 바뀌어 대응하지 않은 멤버는 포함하지 않은 검토 범위다. 원본과의 차이를 확인할 수 있게 된 것이 이번 검사의 목적이다.

## 독립 작성 평가와 검증

별도 에이전트 1회에 최소 원본과 실제 요청을 제공해 두 작업을 평가했다.

1. 원본의 이름·바인딩 변경과 컨트롤 삭제: 기존 크기·Font·AutoHeight·셀 정렬·N2 표시 형식·첨부 분기와 자원 본문을 유지했다. 일반 미사용 선호를 이유로 원본 속성을 바꾸지 않았고, 속성 차이는 요청된 3개뿐이었다.
2. 사용자가 명시한 bool 상태 추가: 상태 저장과 삭제 버튼 제어를 구현했고 첨부 동작은 유지했다. 검사 경고를 이유로 필요한 구현을 막지 않았다.

생성된 실제 코드와 자원을 별도로 대조했다. 이 평가는 오프라인 소스 작업이며 ERP 실행·DB 저장·Designer 렌더링을 의미하지 않는다.

- 도메인 테스트: Python 3.12/3.14에서 각각 255개 통과. 새 회귀 사례 21개 포함.
- Pyright 1.1.413: 60개 파일, 오류·경고 0개.
- 공식 플러그인·10개 스킬 validator, Python 3.11 구문 호환, KH 패키지 검사 통과.

정적 검사는 컬렉션 초기화, 실행 순서, 간접 호출, 전체 C# 의미와 실제 업무 필요성을 보증하지 않는다. 대응되지 않은 삭제·추가와 resx 참조는 요청 및 원본 diff로 별도 대조해야 한다. 스킬 수와 설치 대상 ref는 그대로 유지한다.
