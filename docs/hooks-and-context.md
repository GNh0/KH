# Hooks and context retention

KH bundles a shared Python 3.11+ core with separate Codex and Claude hook adapters. Hooks are short-lived commands: no background observer, extra LLM call, automatic formatter, build, database execution or MCP startup. Existing project coding-style and source-necessity audits remain the main agent's responsibility.

## Host registration and trust

Codex explicitly loads `hooks/codex-hooks.json` through `.codex-plugin/plugin.json`. Claude uses the default `hooks/hooks.json`. Codex runs command hooks through the configured shell, with a Windows command override; Claude uses the documented direct executable/args form. Both need Python available (`python` on Windows/Claude, `python3` on Unix Codex).

Review bundled hooks in the host before use. Codex requires trust for each hook/script hash; an upgrade does not silently grant it. Use `/hooks` or the desktop's Review hooks / Settings > Hooks. No cache, trust database or global configuration is edited by KH. See [Codex hooks](https://learn.chatgpt.com/docs/hooks) and [Claude hooks](https://code.claude.com/docs/en/hooks). Standalone copied skills do not install these lifecycle hooks.

`KH_HOOKS_MODE=advisory` keeps feedback without edit/Stop denial; `off` disables the core. Code checks activate when the current task observably loads a KH SQL, C#/Designer or PB migration entrypoint, or the user explicitly requests that KH domain through the supported Codex invocation syntax below. SQL and C# activate their own domains; PB migration also covers its SQL/C# outputs. Generic context and cleanup skills do not activate code-style checks. File extensions alone never activate them. Within that active scope, default `enforce` requires current domain prerequisites and the complete shared cycle; retries never count as reading. Unknown/malformed input, Python absence, timeout or unsupported host paths remain unverified, not a claimed pass. Host hook failure semantics can allow an action; these are workflow checks, not a security boundary.

Codex activation observes the complete entrypoint in tool returns, including segmented reads. A fresh `UserPromptSubmit` also recognizes explicit `$sql-formatting`, `$csharp-designer-style-harness`, `$pb-to-csharp-migration-harness` and their `kh-uaf:`-qualified forms, including inline requests and the advertised `Use $skill` prompt. A linked `[$skill](absolute-owned-SKILL.md)` or `skill://` selection is matched by its resolved path inside this package, including a line break around the destination; another plugin/app or unresolved/reference-style selection never falls back to the displayed name. Quoted strings, inline/fenced code, Markdown block quotations (including lazy paragraph continuation) and host-only envelopes are excluded. This bounded recognizer does not rebuild the host's global skill catalog; use a qualified name or an exact owned path when names are ambiguous. Ordinary names without invocation syntax do not activate checks.

Explicit selection arms only the requested domain; it does **not** certify delivery of an invisible host-injected body. PreToolUse still requires observed complete entrypoint and cycle bodies. No transcript scan or unrelated task is used to guess a selection. Implicit/invisible host selection without a supported request or returned body remains unverified.

Claude additionally recognizes a successful namespaced `Skill` call and a plugin-owned `UserPromptExpansion` for `kh-skills:<domain>` or `kh-uaf:<domain>`. Another plugin, failed calls and MCP prompts do not activate checks. Native availability records retain hashes/event metadata and bounded previous native evidence, never skill arguments. The entrypoint hash must still match the current source. Every real submission validates pending expansion correlation, including a cold first turn: matching prompt ids preserve that invocation; if neither side has an id, only an exact prompt hash matches. Different or partially missing ids never fall back to text matching. An unrelated pending expansion is removed without discarding independent prior native/body delivery. A permitted source action settles only its directly matching invocation domain into the active audit. PB's SQL/C# output actions retain their audits through independently required domain-body evidence; they do not confirm a pending PB invocation. Later steering or cancellation preserves needed audits without confirming unrelated pending invocations. Submission/Stop/SessionEnd expires correlation keys and previous evidence so a later task cannot reuse them. Native invocation establishes host delivery/selection, not understanding or semantic audit.

After Stop/SessionEnd, the next distinct real user turn clears code-skill activation and prerequisite-read coverage. Same-turn continuation, interruption and compaction preserve an active repair. Pre-scope legacy file results are archived as unverified without inspecting their project source; unsafe snapshot cleanup preserves the originals and prevents a new KH check from adopting the old baseline. Context capture/recovery retains its separate lifecycle behavior.

## What is actually checked

- Before recognized SQL/C#/PB writes within an activated KH domain: the current domain entrypoint must have been delivered by a recognized native invocation or returned completely, and the shared source-style cycle must have been returned completely. An explicit Codex request alone does not satisfy those prerequisites. Other source work receives no KH prerequisite denial, source snapshot, code check or Stop audit. This establishes observed availability, not understanding or a full reference-program audit.
- After writes: domain checks on actual saved files, bounded to 32 files of 1 MiB each. For observed writes, the first pre-edit source remains the comparison baseline across further edits. C# checks receive the conventional code/Designer companion and its captured original. Before/after line hashes separately identify changed text plus adjacent context; returned text can be read in numbered or split ranges. Later edits invalidate affected read evidence. Missing originals remain unverified; the current candidate is never adopted as its own original. No automatic source rewrite occurs.
- Automatic C# context: a bounded scan of explicit unconditional local `Compile`/`ProjectReference` items supplies uniquely resolved, filename-matching control definitions used by the pair. Companion lookup preserves actual filename case and original identities recognize existing Windows aliases. Source/project paths and hashes are recorded; changes to the companion or those dependencies invalidate cached checks. Conditional/dynamic/imported/SDK membership, ambiguous types/projects, runtime initialization and unmatched definitions remain unverified. This is source evidence, not MSBuild evaluation, a complete control catalog or a substitute for reading the actual initialization flow.
- Screen presentation: without an explicit comparison Designer, recorded unchanged visible controls from the original screen can supply same-parent/row or same-type height evidence. The edited control and changed/new peers cannot certify themselves; conflicting or unavailable evidence remains unverified. `same_screen_members` records the selected peers. Compatible height constraints need not copy an unrelated control type's minimum/maximum bounds. Supported Font literals are compared by value, while screen data `EditValue` assignments remain a behavior-audit responsibility. A retained narrower control is not forced wider by an unrelated height edit; new or further width shrink still undergoes the existing rule.
- Review output: errors, counted warning codes, selected findings and `not_checked` remain separate. New warnings produce `status=review_required`, even when the underlying standalone checker has no errors. Unchanged differential findings are suppressed; that does not establish whole-file style compliance. Whole-file imports/style corrections still need standalone checks and actual reference-program comparison. Automatic SQL edits use originals to review new findings; standalone formatting comparisons retain their semantic-preservation checks and do not prohibit authorized logic edits in the hook.
- SQL value sources: added/changed value-producing `ISNULL`/`COALESCE` and supported NULL/blank-guard `CASE`/`IIF` expressions receive `value_fallback_review`. The agent must find the user's explicit request for that substitution in the owning operation or remove the unauthorized change. Initial editor defaults do not authorize SAVE/SELECT substitutions. Unchanged expressions, recognized formatting/alias-only changes and predicate-only NULL handling are separate. This bounded recognizer neither determines user authorization nor covers every equivalent SQL form; full source/requirement audit remains required.
- Cache generation: persisted file results carry the package version and cache schema. A different package version or legacy record without that identity forces a fresh check even when source/dependency hashes are unchanged. This refresh preserves actual readback evidence; it does not turn remaining warnings or unsupported checks into a pass. Unversioned development copies do not reuse persisted checks.
- Before completion: missing readback, static errors, warnings or incomplete checks trigger a bounded continuation request. Readback alone does not resolve a warning. Repeated identical findings or `stop_hook_active` do not loop forever; a repeated unresolved result remains explicitly unverified. The agent must decide findings against actual requirements/source evidence, repair confirmed violations, re-audit and check regressions. No hook certifies semantic compliance or automatically treats a legitimate warning as a defect.

Claude's `PostToolUseFailure` rechecks supported saved destinations that actually changed before failure. An unchanged failed write creates no new saved-file audit; an interrupted failure preserves originals and pauses without starting another inspection. While paused, later tool results/Stop do not inspect source. After explicit `kh_context resume`, Stop reconciles observed write intents against the actual files, including when the completion event never arrived. Each observed file keeps its intent through the edit epoch until Stop; an individual completion cannot consume a later write to that same file. Changed files retain their first immutable original for checking and repair; unchanged intents create no new saved-file audit. Readback ranges use the most recently inspected body so retaining the original intent does not reopen already-read unaffected changes. Codex reports nonzero shell exits through `PostToolUse`, so its adapter keeps that documented event instead of registering Claude-only failure events. Claude's native `PowerShell` tool uses the same bounded destination resolver as supported shell calls. A failure after a partial write is not completion.

Typed Edit/Write/apply_patch and bounded shell-write destinations are recognized. The shell adapter resolves common straight-line Python `Path`/string assignments and writable `open`, and simple PowerShell assignments, `Join-Path`, interpolation, content commands and `IO.File` writes. Python is recognized in invoked PowerShell here-strings, simple `python -c` and heredoc forms. Resolution uses the command's actual workdir and never executes the program to discover paths. A recognized but unresolved source-shaped destination is denied in enforce mode; it is not treated as a successful check. Quoted examples, comments, read-only operations and non-domain output files do not become domain edits.

This is a bounded syntax adapter, not a filesystem sandbox: functions, arbitrary control flow, external scripts/inputs, unsupported invocation forms, hosted tools and specialized host operations can still escape observation. It does not promise to detect every dynamic write. Source bodies returned with line-number decorations, truncation or encoding differences may need a direct complete UTF-8 read. During an active edit, known files are rechecked on later events. A clean Stop retires that edit set and keeps compact results for scoped recall; later read-only work does not keep reviewing completed files or other chats' subsequent changes. A new observed edit starts a new comparison epoch. Existing limits on builds/DB/other external actions still apply.

Pre-edit source bodies are content-hashed files under the existing external context store's `checks/<session-key>` directory, never under the project or plugin cache. SQLite records identities, not those bodies. At most 64 source/companion identities of 1 MiB are captured. A clean Stop deletes unchanged task-owned snapshots after preflighting the directory; unexpected/tampered files are preserved and cleanup is reported unverified. Unfinished reviews, interruption and compaction retain needed originals. These source snapshots are ordinary local files, not a credential vault. Scoped `kh_context.py recall` exposes saved check summaries/context when the short hook message omits files; it does not print snapshot bodies.

After a prior edit reaches Stop, the next distinct real user turn retires that earlier active set. Unresolved results are archived as `previous_turn_unverified`, never relabeled as passed; recall distinguishes them from current active checks. This also handles pre-upgrade sessions that retained a `stop_notice` without an epoch marker. A new observed edit captures its current pre-edit source. Same-turn steering, native Stop continuation, compaction, interruption and an explicit stop request preserve the active repair and needed originals. Cleanup still preflights ownership; a failed cleanup preserves the records and reports the limitation. Upgrading during an active turn does not infer a new task boundary.

## Legacy Codex notification errors

`legacy_notify` is Codex's global `notify` command, separate from KH's registered lifecycle hooks. Its JSON payload travels as a command-line argument; Windows error 206 can occur before that command starts. A wrapper that receives the same oversized argument does not repair that transport. When an obsolete `codex-computer-use.exe turn-ended` notification is present, first verify the enabled installed computer-use plugins already register their native `Stop`/`Interrupt` lifecycle hooks. An explicitly authorized repair can then remove only that duplicate notification, preserving the native hooks and all other settings. Do not remove arbitrary notifications or add a second CUA owner to KH. KH does not automatically rewrite global host configuration or grant hook trust.

## Compaction and durable memory

`PreCompact` saves current-chat user evidence/source locations and existing curated checkpoint. Both Codex and Claude restore through `SessionStart(source=compact)`, with duplicate suppression. A paused task or pending source audit still receives scoped recovery guidance when no user record/checkpoint was captured; lack of archived text must not erase the pause notice. Codex delivers this context before the next model request, including an immediate continuation after automatic compaction within a turn. `PostCompact` does not support context injection and is not registered by KH. Startup/resume loads the same chat's checkpoint plus explicitly curated project memories. A new chat does not inherit another chat's task checkpoint. Interruption preserves needed continuation data and does not restart the task.

Recovery is a bounded preview with original source locations. It is not a second summary that silently replaces the originals. Latest corrections/cancellations take precedence, a checkpoint records its user-record cursor, and incomplete capture is reported. The latest observed UserPromptSubmit is preserved separately even while a large transcript has pending capture; older uncaptured details still require the original log/checkpoint. Supported Codex/Claude transcript adapters are version-sensitive because host transcript formats are not stable public APIs. Images, attachments, deleted logs and unsupported formats remain unverified.

Codex capture accepts both desktop `response_item/message/role=user` text parts and `event_msg/user_message`. Adjacent mirrored representations share one archive record with both source locations; separate repeated requests remain separate. Sequence ids remain stable archive identifiers, including after backfill. Recovery, recall and search previews order comparable records by their offsets in the same selected transcript, so later insertion of historical records cannot displace the latest source correction. The most recent unlinked prompt event is retained with explicitly unverified source order. A checkpoint's additional-record count can include historical backfill and is not a count of newer user requests; recovery shows recent evidence before a long checkpoint. No total chronology between different logs or unlinked events is inferred. Adapter upgrades rewind the selected transcript once and backfill in bounded passes, preserving existing archive identifiers, checkpoints and pause state. A fully read log with no supported user records is reported as unverified rather than successfully preserved.

Native `<hook_prompt ...>...</hook_prompt>` Stop continuations are host feedback, not user requests or new edit boundaries. Capture excludes these envelopes and removes previously misclassified archive entries without renumbering real user records or reusing ids. New checkpoint cursors use archive sequence ids, so filtered gaps do not hide later corrections. A user message that quotes an envelope and adds a request outside it remains user evidence.

Use [context handoff](../skills/context-handoff/SKILL.md) to save a critical task checkpoint or explicitly requested long-term project fact. Storage is outside project/cache trees and isolated by project/chat; no native global memory is edited. Local archival is not promotion of all historical requests into permanent user preferences.

Verification must distinguish local event replay, a real host firing registered hooks, and actual model source/audit behavior. Unit passes or a saved checkpoint alone establish neither host invocation nor complete model compliance.
