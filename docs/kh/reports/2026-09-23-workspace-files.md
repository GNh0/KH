# KH 3.0.10: 프로젝트 파일 정리

사용자가 보여준 실제 프로젝트 상위 폴더에는 `.codex_tmp`, `.pbl-analysis`, `Codex_work`, `outputs` 등 작업용 폴더가 함께 있었다. 각 폴더의 생성 주체를 모두 KH로 확정할 수는 없다. 다만 KH의 PB ORCA 실행기에는 출력 경로를 생략하면 PBL 옆에 새 폴더를 선택하는 코드가 있었다.

이번 변경은 C#·SQL·PB 및 실행·검토·디버깅 스킬에서 보조 스크립트, 검사 결과, 스냅샷과 분석용 추출 파일을 시스템 임시 위치의 작업별 폴더에 두도록 안내한다. 실제 소스 변경과 사용자가 지정한 최종 산출물은 해당 위치에 작성한다. 작업이 끝나면 자신이 만든 임시 파일만 확인해 정리하며 기존 파일은 출처를 확인하지 않고 지우지 않는다.

PB ORCA `probe`는 출력 경로 없이 계속 실행 환경을 읽을 수 있다. `convert`는 명시적인 출력 경로가 없으면 외부 추출 도구를 실행하지 않고 `output_directory_required`를 반환한다. 기존 입력 파일 옆에 자동으로 출력 폴더를 만드는 경로를 제거했다. 분석용 변환에는 프로젝트 바깥의 작업별 임시 위치를 지정하며, 사용자가 최종 출력 위치를 정한 경우 그 경로를 따른다.

검증: 출력 경로 생략 시 PBL 옆에 디렉터리를 만들지 않는 회귀 테스트를 포함해 도메인 테스트 256개와 KH 패키지 검사가 통과했다. 별도 스킬/플러그인 validator는 로컬 Python에 PyYAML이 없어 실행하지 못했으며, 패키지 검사는 manifest·스킬 링크·Python AST와 내부 import를 확인했다. 기존 프로젝트 폴더의 파일 정리와 현재 설치된 플러그인 캐시 갱신은 이 소스 변경에 포함되지 않는다.
