# KH 3.0.3 C# 작성 방식과 사용자 컨트롤 기본값

사용자 컨트롤을 두고 기본 컨트롤을 선택하거나 초기화 속성을 화면에서 임의로 덮어쓰는 문제와, 3.0.0 재구성에서 누락한 구체적인 Name 규칙을 보완했다. 이 기준은 KoneLib에 한정되지 않으며 C#/Designer와 PB→C# 스킬이 함께 사용한다.

## 확인한 근거와 누락

사용자가 지정한 실제 솔루션에 포함된 BA·SA·MA 화면 7개의 code-behind 2,181줄을 읽고 대응하는 Designer 7개 14,111줄의 선언·속성을 분석했다. 기존에 합의한 명시적 규칙을 우선하고, 샘플의 생략된 중괄호·미완성 메서드·자동 생성 이름 등은 새로운 작성 기준으로 채택하지 않았다. 업무 소스와 개인 경로, 대화 원문은 공개 패키지에 복사하지 않았다.

2.9.147의 csharp_designer_style_contract.py와 pb_to_csharp_migration.py에는 컨트롤 종류별 접두사 및 grd/gvw/col/rps 명명 검사가 있었다. 3.0.0에는 일부 PB 이름 생성과 일반적인 프로젝트 이름 준수 문구가 남았지만 구체적인 C# 검사가 빠졌다. 이는 중복 스킬 통합만으로 정당화되는 제거가 아니며, 이번에 복구했다.

참조 작업에서는 날짜 입력 이름과 서식 추가를 사용자가 다시 정정했다. 새 검사 이전에는 일반 사용자 컨트롤의 실제 상속·생성자 기본값을 입력받아 비교하는 경로도 없었다. 규칙을 알고 있다는 설명만으로 선택·초기화·연결을 검증한 것으로 취급하지 않는다.

## 적용한 기준

- [C# 작성 방식](../../../skills/csharp-designer-style-harness/references/coding-style.md): 명시적 타입, 전체 get 본문, 중괄호, 생성자의 이름 있는 이벤트 핸들러 연결, 실제 프로젝트의 helper·SP·XML·저장 흐름과 파라미터 배치를 따른다. 기존 LINQ·중간 테이블·빌드 비선호와 사용 예외 기준은 유지한다.
- [사용자 컨트롤](../../../skills/csharp-designer-style-harness/references/user-controls.md): 현재 프로젝트에서 사용할 수 있는 적절한 컨트롤을 우선한다. 생성자·InitializeComponent·초기화 helper·상속 부모를 읽고 기본 속성을 유지한다. 화면에는 이름·배치·표시 문구·바인딩·이벤트와 실제 요구 속성을 지정한다. 다른 라이브러리에도 적용하며 전역 폰트·크기 표를 만들지 않는다.
- 이름: txt/Spin/ymd/cbo/btn/Chk/memo, pn/grp/grd/gvw, col<Role>_<FIELD>와 Repository 규칙을 복구했다. 선언과 Name 불일치 및 새 자동 생성 이름을 검토한다. 기존 화면 전체를 강제 개명하는 규칙은 아니다.
- 숫자 Repository: 기본은 rpsSpin<Field>다. List의 rpsSpinQTY가 이미 있고 Detail에 별도 Repository가 필요하면 기존 이름을 유지하고 rpsDetailSpinQTY를 만든다. 생성기는 기존 이름 목록을 받아 선언·Name·등록·ColumnEdit에 같은 이름을 쓰며, 역할 이름까지 충돌하면 임의 숫자를 붙이지 않고 충돌을 보고한다.
- 날짜 입력: ymdFRDT/ymdTODT처럼 실제 필드와 연결한다. 날짜라는 이유만으로 DisplayFormat·EditFormat·EditMask를 추가하지 않는다. 실제로 필요한 연→월→일 이동 등은 해당 컨트롤의 구현과 요청을 기준으로 유지한다.
- [3.0.2 그리드 기준](2026-09-08-grid-style.md): 사용자 HTML 기본값, 셀/헤더 Appearance, 세 가지 컬럼 편집 모드, OptionsBehavior 보존과 SpinEdit/DisplayFormat 기준은 그대로 유지했다.

새 --control-source 옵션은 실제 사용자 컨트롤 소스를 직접 받는다. 제공된 상속 관계와 기본 생성자의 직접 대입을 비교하여 새 덮어쓰기는 경고, 동일 기본값 재대입은 정보로 표시한다. Name·Location·TabIndex·바인딩 필드처럼 화면이 정하는 값은 기본값 덮어쓰기 경고에서 구분한다. 현재 원본과 동일한 속성을 일괄 정리 대상으로 만들지 않는다. 검사기의 일반 스타일 경고가 구현 금지나 별도 승인 절차를 뜻하지 않는다.

## 검증과 한계

Python 3.12.14와 3.14.2에서 회귀 검사 175개를 통과했다. 3.0.2보다 38개 늘었다. 상속·조건부 대입·이름 충돌·원본 보존·주석/문자열·중첩 제어문과 변경된 중괄호 생략을 검사한다. Pyright 1.1.413은 57개 파일에서 오류·경고 0건이다. 타입 검사 범위를 완화하거나 런타임을 TypeScript로 바꾸지 않았다.

공식 플러그인 검증, 10개 스킬 검증, 패키지 링크·내부 import 검사와 Python 3.11 문법 검사를 통과했다. 두 스킬의 프로필은 동일하며 기존 grid_layout 정책도 보존했다.

독립 사용 평가 두 건에는 수정 스킬, 최소 입력 소스와 실제 작성 요청만 전달했다. 첫 결과는 조회·수량 검증·선택 행 추가를 기존 C# 흐름에 맞춰 작성하고 기존 Designer를 보존했다. 두 번째는 KoneLib가 아닌 일반 예시 라이브러리를 제공했다. 결과의 9개 컨트롤이 모두 제공된 사용자 컨트롤이었고, 폰트·크기·AutoHeight·마스크를 화면에서 덮어쓰지 않았으며 날짜·텍스트·숫자·버튼 이름과 이벤트 연결도 확인했다. 루트 검토자가 실제 산출물을 읽고 정적 검사를 다시 수행했으며 입력 파일 해시가 유지됐다.

이 평가는 두 건의 정적 사용 결과다. 향후 모든 작업의 준수율, 실제 화면 품질이나 클릭 동작을 입증하지 않는다. 검사기는 helper 호출, 제공되지 않은 partial/상위 초기화, 조건과 실행 중 값, 실제 프로젝트 참조 가능성을 완전히 평가하지 않는다. 이 항목은 코드 작성 중 실제 소스로 확인해야 한다.

업무 소스 14개와 기존 미추적 파일 25개의 해시를 보존했다. 업무 소스 변경, ERP 빌드, Visual Studio Designer 렌더링과 DB/PB 실행은 수행하지 않았다. [검증 JSON](2026-09-08-csharp-user-controls.json)에 결과 범위를 기록했다. GitHub 게시와 설치 캐시 갱신은 별도이며, 새 소스가 실행 중 작업의 이미 로드된 스킬을 자동 교체하지 않는다.
