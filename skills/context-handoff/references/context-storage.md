# Checkpoints and scoped recall

The local standard-library helper stores data in the host's `PLUGIN_DATA`/`CLAUDE_PLUGIN_DATA` directory, falling back to the user's local KH data directory. Project paths are hashed; current task records are additionally isolated by host, chat id, transcript and agent id. It writes no checkpoints into the project or plugin installation. No MCP, daemon, embedding service or extra model call is needed.

Use `python -B <absolute-plugin-root>/scripts/kh_context.py --cwd <absolute-working-directory> --session <current-host-session-id> --transcript <exact-current-jsonl-path> --host codex <command>` (`--host claude` on Claude). Include `--agent-id` if the host supplies one. Never substitute another chat's id or find the "most recent" log across the machine. Get identifiers from the current host context; if unavailable, use an explicit handoff artifact in the authorized external working directory and report that automatic restoration is unavailable.

- `checkpoint --file <absolute-UTF8-input>` saves a concise task checkpoint, at most 12,000 characters. Use an external task-owned temporary input and remove it after verifying `recall`. Include exact critical constraints, superseded/cancelled work, files, actual results, unverified limits and the next action. The checkpoint's user-record cursor shows what later corrections may invalidate it.
- `recall` returns the current checkpoint, latest user evidence, changed-file check state and curated project memory. A file/hash/read record is not an agent audit result.
- `get <seq>` retrieves one archived user record without preview shortening; `memory-get <id>` retrieves one complete durable entry. A `truncated` record still needs its original transcript source. Search/restore previews explicitly mark shortening and retain source pointers.
- `get-prompt <id>` retrieves a prompt captured while the transcript was incomplete. Such prompts remain separately searchable in order, so a later status question cannot erase an uncollected correction or cancellation. Recovery diagnostics and recall instructions reserve output space before preview shortening.
- `search "기본 정렬"` retrieves matching user evidence only from this chat and explicit project memories. Korean is retained; matching is literal case-insensitive terms, not semantic search. No match is not proof that an instruction never existed. Check capture diagnostics and original source locations.
- `remember <stable-id> --file <absolute-UTF8-input>` explicitly adds/replaces a user-authorized durable **project** fact. Include provenance and scope in the text. `forget <stable-id>` removes it. Read existing entries first; do not overwrite unrelated facts. Entries are limited to 4,000 characters, total 32,000 per project; excess is rejected rather than silently discarding old constraints. This is not the native host's global memory.
- `resume` clears this chat's hook pause only after the user explicitly resumes the task. A status question never clears interruption. Do not use this command to override a stop request.

Bundled hooks archive user records before compaction and preserve original transcript offsets/hashes, plus redacted text capped at 64,000 characters per record. They never archive reasoning or tool bodies. A large/unsupported/incomplete transcript produces diagnostics; a preview cut is not a complete read. The native transcript remains necessary for huge entries, images and attachments. Structured secrets are masked on a best-effort basis; do not deliberately submit secrets as memories.

After compaction/restart, inspect later records before trusting a checkpoint. The hook injects only a bounded recovery preview; use `recall`/`search` and the original transcript for missing details. Revalidate files and pending runtime ownership. Do not replay completed DB writes, deployments or cancellations merely because they appear in older evidence.
