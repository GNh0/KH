# User's grid defaults

Use the `generateDevExpressXml` output from the user's `DataWindowToXml.html`, supplied on 2026-09-08, as defaults for new WinForms/DevExpress grids. Do not copy arbitrary options from other screens or recommended DevExpress example settings alongside them. Preserve user edits and actual behavior in existing screens; change only properties needed for new requirements. Do not extend these rules to reports or other UI frameworks.

## Appearance

| Scope | Properties generated by default |
| --- | --- |
| AppearanceCell | Options.UseFont=true, Font=Tahoma 9pt |
| AppearanceHeader | Options.UseFont=true, Options.UseTextOptions=true, TextOptions.HAlignment=Center, TextOptions.VAlignment=Center, Font=Tahoma 9pt |

Omit cell `TextOptions` and `Options.UseTextOptions`, including explicit defaults such as Near/Far/Center. Numeric, date, or text data alone does not justify extra cell alignment. Retain header UseTextOptions, which enables centered headers. Tahoma 9pt applies to grids newly generated from this HTML; it does not override user-edited Font values or every UserControl's font.

## Column editing

| Required behavior | OptionsColumn.AllowEdit | OptionsColumn.ReadOnly |
| --- | --- | --- |
| Block ordinary editing | false | true |
| Allow actions such as a Button Repository, but block value changes | omit | true |
| Editable / HTML defaults without a separate editing requirement | omit | omit |

Omission does not mean writing `AllowEdit=true` or `ReadOnly=false`. When a request changes these existing properties, remove assignments that are no longer needed. Determine behavior from the actual Repository type, connected events, and requested actions, not the button name alone.

This HTML contains no `GridView.OptionsBehavior`. Do not add view-wide `Editable=false` or `ReadOnly=true` to implement column editing restrictions. Do not add, change, or delete existing values during unrelated work. The [DevExpress Editable documentation](https://docs.devexpress.com/WindowsForms/DevExpress.XtraGrid.Views.Base.ColumnViewOptionsBehavior.Editable) states that the view's Editable controls editing in both cell editors and the Edit Form. Column [ReadOnly](https://docs.devexpress.com/WindowsForms/DevExpress.XtraGrid.Columns.OptionsColumn.ReadOnly) is separate; do not treat them as substitutes. Check the installed version and event behavior as needed.

## Display and numeric editors

- Do not set either `DisplayFormat` member, `FormatType` or `FormatString`, by default. A date column alone does not justify adding DateTime/`yyyy-MM-dd`.
- Connect numeric columns to the actual Spin Repository without automatically adding `Mask.EditMask`, including `N0`/`N2`. Do not use this rule to remove required DateEdit input masks wholesale.
- For display problems, first inspect actual data types, bindings, and existing Repositories. Add only the necessary mask/format properties when the requested behavior would be difficult to implement without them, and record why. Convenience does not justify expanding defaults.

## Verification after changes

Check new defaults and column editing modes. For existing-screen edits, compare against the original to detect unrequested option additions, changes, or deletions. You may supply originals and explicit column modes to the [checker](checks.md). Style warnings are review items; they do not justify blocking implementation or deleting existing options wholesale. Passing checks do not establish actual Designer execution or button-event behavior.

SummaryItem.DisplayFormat and the Summary constructor's format argument apply in different locations from ordinary cell/Repository DisplayFormat. Use [custom numeric formats](coding-style.md) for required summaries without adding DisplayFormat/FormatType to columns or Repositories on that basis.
