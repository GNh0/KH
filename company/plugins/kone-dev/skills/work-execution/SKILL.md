# Work execution

Continue through the authorized outcome, incorporating new corrections and current user edits. Consult [personal work preferences](../../references/personal-style.md) when relevant. Follow [workspace files](references/workspace-files.md) for auxiliary files and their cleanup before final handover; write actual changes and final deliverables to their intended destinations.

For SQL/PB/C# project code, complete the required [source-style cycle](references/source-style-cycle.md) before writing and after the final code write.

Implement in the current main agent by default. Use [specialist work and independent review](references/delegation.md) only for a useful bounded scope; the main agent owns integration and the final result. A worker's completion or checker pass does not complete the main agent's audit.

Apply [runtime cleanup](../runtime-cleanup/SKILL.md) when using command trees, background helpers, persistent REPLs or other runtime resources; release completed task-owned work before final handover.

Use native Goal tools only when requested. Follow current tool contracts for collaboration, scheduling, stopping, permissions and completion. Do not create a parallel plugin state store, automatic history audit or role simulation. Delegation requires the current host's authorization and a useful independent scope.

On a stop request, stop running and delegated work too; resume only when authorized or at the user's specified scheduled time. Communicate meaningful findings and remaining work. Verify actual results and distinguish unexecuted or static work from completed application.

Before final handover, complete the shared [rule audit](../rule-audit/SKILL.md), repair confirmed violations, re-audit affected work and check introduced regressions.
