# KH 3.0.1 검사기 보강

3.0.0 실제 평가에서 재현된 오탐·누락을 수정했다. Python 실행 검사기를 유지하고 정적 타입 검사와 외부 입력 검증을 보강했다. 스킬 10개 구성과 기존 원격 marketplace/ref는 유지한다.

| 발견 | 수정 |
| --- | --- |
| 지역 `Where()` 선언/호출을 LINQ로 판단 | 실제 선언과 호출을 구분하고 불확실한 API는 후보 경고로 표시 |
| 트랜잭션 wrapper 이름 변화만으로 오류 확정 | 이름 기반 변화는 검토 경고, 실제 인자·본문·API 확인 필요 |
| 한 줄의 여러 Designer 속성 비교 누락 | 문자열/주석을 분리한 문장 경계로 속성 읽기 |
| 같은 문자열 값의 일반/verbatim 표기 차이를 변경으로 판단 | 일반·verbatim·raw 상수의 실제 값 비교, Unicode escape와 UTF-16 처리 |
| `global::`로 한정한 매개변수 생성자 누락 | 전역/alias 한정 이름과 상수 문자열 이름 인식 |
| Python 컨테이너 비교에서 `True == 1` | 중첩 JSON 타입과 값 비교, 잘못된 입력은 구조화된 미완성 결과 |
| `dw.DataObject` 리터럴 대입 누락 | 대입/비교·문자열 예문을 구분하고 동적인 값은 미확인으로 기록 |
| DW 조회문에 속성 선언 뒷부분까지 포함 | retrieve 값·PowerScript SQL·동적 문자열 후보를 분리하고 원본 위치/완전성 표시 |

인접 경계도 확인했다. 계산식 매개변수 이름은 누락으로 단정하지 않고, SQL 안의 SQL처럼 보이는 문자열은 별도 조회문으로 중복 추출하지 않는다. 순환/비유한/잘못된 JSON 입력과 boolean 시간 표본은 비교 성공으로 처리하지 않는다.

독립 C# 사용 평가에서 명시적인 속성 보존과 SP 비교 기능을 문서의 CLI만으로 찾기 어렵다는 점을 확인해 `designer --preserve-property`와 `sp-call` 명령을 추가했다. OUTPUT/INPUTOUTPUT 방향과 반환값 회수는 검사하지 않음을 결과에 표시한다. 줄바꿈 LF/CRLF는 문자열의 실제 값이므로 임의로 같다고 처리하지 않는다.

타입 검사 결과는 기존 51개 파일의 오류 10건·경고 1건에서 최종 52개 파일의 오류·경고 0건으로 바뀌었다. 진단 10건이 모두 실행 버그였다는 뜻은 아니다. 상당수는 Optional 값의 좁히기나 `TextIOWrapper`/severity의 타입 계약이 불명확한 문제였다. bool/int 동등 비교와 파서의 이름·줄 단위 가정은 별도의 동작 회귀 검사로 발견하고 수정했다.

| 검증 | 실제 결과 |
| --- | --- |
| Python 단위 검사 | 113개, Python 3.14.2와 3.12.14 각각 통과; 기존 86개에 반례 27개 추가 |
| 원래 평가 입력 재실행 | 검사 범위 내 39개 모두 일치; 이전 33/39 |
| 정적 타입 검사 | Pyright 1.1.413, 전체 standard + 입력 경계/C#/PB lexer strict |
| 독립 사용 평가 | C#·PB 각 1개 작업 완료; 정답을 주지 않고 최소 원본과 스킬 복사본만 제공 |
| 새 CLI 최종 확인 | 실제 Designer 변경 2개를 실패로 검출, SP 이름 비교와 PB 입력 분석 수행 |
| 공식 패키지/스킬 검사 | manifest와 스킬 10개 유효, Python 3.11 문법 검사 통과 |
| 원래 로컬 작업 자료 | 기존 미추적 파일 25개 해시 보존; 이번 공개 변경에 포함하지 않음 |

독립 평가 두 건이나 반례 39건만으로 일반 업무 정확도가 100%라고 주장하지 않는다. 완전한 SQL 문법, 같은 시그니처의 업무 수식, PB 이벤트 본문 동등성, PDF 객체 그래프, OOXML 관계/렌더링은 기존 선언 범위 밖이다. 실제 ERP 빌드·SQL Server·native PB/ORCA 작업은 수행하지 않았다. GitHub 자동 검사 설정과 원격 실행 결과도 구분한다.

Python을 TypeScript로 전면 교체할 근거는 이번 평가에서 나오지 않았다. [Python 타입 주석](https://docs.python.org/3/library/typing.html)과 [TypeScript 타입 주석](https://www.typescriptlang.org/docs/handbook/2/basic-types.html)은 그 자체로 외부 입력을 실행 중 검증하지 않는다. 현재 필요한 조치는 [타입·회귀 검사](../../development.md), 입력 검증, 실제 문법 경계에 맞는 판정이다. 언어 전환은 별도의 런타임/생태계 요구가 생길 때 검토한다.
