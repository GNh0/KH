# KH 3.0.6 — 대상 프로젝트의 이벤트·데이터 처리 방식

두 C# 이관 작업의 사용자 정정, 실제 작성 기록과 코드 변경을 대조했다. 기존 스킬을 읽고 검사까지 실행한 상태에서도 현재 화면의 조회 흐름과 공통 API를 따르지 않는 변경이 반복됐다. 이번 변경은 해당 선택을 작성 전에 확인하도록 스킬을 보강하고, 정적 검사에서 검토 후보를 표시한다.

## 확인한 문제와 수정

| 확인한 문제 | 반영한 내용 |
| --- | --- |
| 원본이나 비교 화면의 이벤트 본문을 현재 화면의 상태 확인 없이 복사 | 원본은 업무 동작, 대상 프로젝트는 구현 방식의 근거로 구분한다. 이미 연결된 헤더·상세·조회 경로를 먼저 읽는다. |
| 신규/수정 진입 때 불필요한 조회·재바인딩, 공통 초기화·날짜 API 누락 | 실제 스키마와 초기화 범위를 확인하고 기존 API를 우선한다. 새 진입 조회와 실제 날짜 API 우회 후보를 경고한다. |
| 서버 담당 순번·키 대입, 임의 저장 제약, 수동 선택 행 삭제 | 현재 XML/SP와 GridView 계약을 대조하도록 지침과 검토 경고를 추가한다. |
| 대상이 직접 이벤트 처리하는데 새 조회·선택 행 wrapper를 생성 | 새 helper 선언을 원본과 비교한다. 기존 메서드의 빈 본문 구현은 별도로 취급한다. |
| 연동 원본을 주석 보존하라는 요청에 설명문·빈 메서드로 대체 | 전체 원본 본문과 비활성 실행 경로를 각각 대조하도록 명시한다. 원본에서 주석인 JOIN·검증도 임의 활성화하지 않는다. |
| 사용자 지적 후 같은 선택을 재작성본에 다시 추가 | 같은 변경의 검증·초기화·재조회·wrapper까지 재검토하고, 이후 사용자 수정을 과거 사본으로 덮지 않는다. |
| 여러 참고 파일 출력이 잘렸는데 읽기 완료로 취급 | 필요한 부분의 실제 출력 확인을 요구한다. |
| 정적 `passed`를 전체 스타일 준수로 설명 | C# 결과 앞부분에 `review_status`와 `project_style_verified=false`를 표시한다. |

필요한 조회·검증·helper를 일괄 금지하지 않는다. 경고는 현재 요구와 실제 API·저장 계약을 확인할 지점이며 자동 삭제나 승인 요청의 근거가 아니다.

## 실제 실패 코드 재검사

작업 기록의 변경 전 사본과 전체 diff를 대조해 최초 작성본을 복원했다. 같은 C#·Designer·실제 날짜 컨트롤 소스를 3.0.5와 수정본에 제공했다.

| 항목 | 3.0.5 | 3.0.6 |
| --- | ---: | ---: |
| 정적 오류 | 0 | 0 |
| 검토 경고 | 0 | 14 |
| 프로젝트 스타일 검증 완료 표시 | 별도 필드 없음 | false |

14개는 실제 날짜 API 4개, NEW/EDIT 진입 조회 2개, 저장 조건 4개, 순번 계산 1개, 새 상세 행의 헤더/문맥 필드 복사 2개, 선택 행 삭제 1개다. 이는 14개 업무 오류가 확정됐다는 뜻이 아니다. 이전에 보이지 않던 검토 지점을 드러낸 결과다.

## 독립 작성 평가

실패 기록과 정답 코드를 제공하지 않은 별도 에이전트에게 수정된 스킬, 미완성 화면, 이관 원본과 대상 API/저장 계약 조각을 제공했다. 신규·수정·추가·삭제·저장을 구현하고 원본 연동을 주석으로 남기는 요청이었다.

생성한 실제 코드를 다시 읽고 다음 12개 조건을 확인했다: 기존 초기화 사용, 진입 시 기존 조회 상태 유지, 수정 시 모드·화면 전환, 기존 포커스/탭 바인딩 유지, 선택 행 삭제 API, 원본의 추가 필드 유지, 서버 키 미중복 계산, 대상 저장 계약, 임의 저장 제약 미추가, 기존 성공 처리, 연동 전체 본문 주석 보존, 새 wrapper 미추가. 모두 충족했다.

이는 오프라인 소스 작성 시나리오 1건의 결과다. 실제 ERP 화면 실행·DB 저장·컴파일 결과를 뜻하지 않는다. 원본 주석 본문 보존은 생성 결과의 실제 본문을 별도로 대조했고, 정적 검사기의 자동 보증 범위에는 포함하지 않았다.

## 검증 범위

- Python 3.14.2와 3.12.14에서 도메인 테스트 각각 234개 통과.
- Pyright 1.1.413: 59개 파일, 오류 0개·경고 0개.
- 새 회귀 테스트 23개: 기존 처리 보존, 이벤트 간 조회 이동, 필요한 스키마 조회, 저장 조건, 행 처리, 실제/상속/미제공 날짜 API, 새 helper와 기존 본문 구현, 주석·문자열과 결과 범위 표시를 확인한다.
- Python 3.11 구문 호환 확인, 공식 플러그인·10개 스킬 validator 및 KH 패키지 검사 통과.

정적 검사는 C# 전체 의미, 간접 호출과 조건별 실행 순서, 실제 서버 필드 소유권을 판정하지 않는다. 경고가 없어도 현재 화면과 사용자 요구의 대조가 필요하다. 스킬 수는 10개를 유지하며 프로필과 설치 대상 ref는 변경하지 않는다.
